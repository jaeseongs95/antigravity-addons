# Architecture & Vendor Independence

`antigravity-native-addon-host` follows a strict hexagonal (Ports & Adapters) design with SOLID ISP/DIP enforcement across `src/core/`, `src/cli/`, and `src/adapters/electron/`:

- **`src/core/` (Vendor- & Runtime-Neutral Policy — `TC-001`, `TC-023`)**:
  - `fs-port.js`: runtime-neutral `FileSystemPort` abstraction (`existsSync`, `isFileSync`, `realpathSync`, `resolve`, `normalize`, `relative`, `isAbsolute`, `join`, `sep`) so `src/core/` has zero direct `node:fs` or `node:path` imports.
  - `host-profile-port.js`: minimal runtime-neutral `HostProfile` contract (`id`, `resolvePaths`). Contains zero Electron, ASAR, or vendor fields.
  - `host-ports.js`: segregated CLI ports (`HostLifecyclePort`, `AddonStorePort`) so CLI depends only on small host-neutral abstractions.
  - `manifest-validator.js`: compiles and enforces `schemas/addon-manifest.v1.schema.json` via `ajv`, strict SemVer 2.0.0 compatibility comparison (fail-closed + prerelease precedence), explicit `trustLevel` (`trusted` | `restricted`) + `strictTrustPolicy` enforcement, and `<pluginsRoot>/<pluginId>/` realpath symlink confinement via injected `FileSystemPort` (`createManifestValidator({ fsPort })`).
  - `slot-registry.js`: null-prototype (`Object.create(null)`) exclusive slot, `storageNamespace`, and `ipcChannelPrefix` collision detector.
  - `lifecycle-coordinator.js`: deterministic `(loadOrder, pluginId)` sorting, duplicate `pluginId` rejection, read-only enabled-gate filtering, and fault-isolated execution planning.
- **`src/cli/` (Host-Agnostic CLI Factory — `TC-001c`)**:
  - `main.js`: `createCliApp({ hostLifecycle, addonStore, defaultProfile })` resolves an opaque host context strictly once per CLI invocation, delegates `--validate`/`--register`/`--unregister`/`--status`/`--doctor`/`--install` (including `--replace-legacy`, `--refresh-orig`)/`--rollback` exclusively through `HostLifecyclePort` and `AddonStorePort`, and has zero `ctx.paths` assumptions, zero `node:fs` writes/locks, zero Electron/ASAR fields, and zero concrete adapter/profile imports.
- **`src/adapters/node-fs-port.js` & `src/adapters/fs-lock-atomic.js` (Host-Neutral I/O, Lock & Atomic Write Utilities — `TC-001d`, `TC-023`)**:
  - `node-fs-port.js`: Node.js implementation of `FileSystemPort` injected into `src/core/` by adapters.
  - `fs-lock-atomic.js`: standalone `proper-lockfile` exclusive locking and atomic rename-write helpers with zero `@electron/asar` or `acorn` coupling.
- **`src/adapters/electron/` (Electron Host Adapter — `TC-001b`, `TC-001d`, `TC-019`–`TC-022`)**:
  - `electron-host-profile-port.js`: validates Electron/ASAR/URL fields and required resolved paths (`ADDONS_DIR`, `PLUGINS_ROOT_DIR`, `LOADER_SCRIPT_PATH`, `ASAR_PATH`, `ASAR_LOCK_PATH`).
  - `electron-host-lifecycle-port.js` & `electron-addon-store-port.js`: segregated `HostLifecyclePort` and `AddonStorePort` implementations. `installHost` executes transactionally (stages `addon-host-loader.js` under `ADDONS_LOCK_PATH` first, then patches `app.asar`, and automatically compensates by restoring or removing the staged loader on any ASAR failure). `electron-addon-store-port.js` depends only on `fs-lock-atomic.js` and `node-fs-port.js`, never on `asar-patcher.js`.
  - `config-reader.js`: read-only fail-closed `config.json` reader using `Object.hasOwn`.
  - `asar-patcher.js`: `@electron/asar` + `acorn` character-offset (`[start, end]`) exact-size patcher and syntax verifier (CJS, ESM, Hashbang, `\r`/`\u2028`/`\u2029` safe), `.orig` build-hash identity guard (`ERR_ORIG_BUILD_MISMATCH` unless explicit `--refresh-orig` archives previous `.orig`), recorded `patchedSha256` verification before rollback (`ERR_PATCHED_ASAR_UNEXPECTED_MODIFICATION` unless `--force`), canonical lock ordering (`ADDONS_LOCK_PATH` -> `ASAR_LOCK_PATH`), and legacy direct-patch doctor.
  - `host-loader-builder.js`: generates the shared `addon-host-loader.js` using `executeJavaScriptInIsolatedWorld` (with main-world fallback), `'use strict'` + `Reflect.apply` + null-prototype descriptors, CSS owner auto-scoping (`[data-addon-host-owner="<pluginId>"]`) + dangerous CSS rejection + opt-in Shadow DOM, least-privilege frozen `mainHook` & `webContents` brokers with automatic listener cleanup, explicit addon lifecycle state machine (`getAddonLifecycleStates()`), async `activate()`/`dispose()` rejection & timeout isolation, `addonHost.runSafe()`/`reportError()`/`addManagedListener()`, protocol+host+non-`'null'` origin verification, separated pending vs committed navigation lifecycle, partial-throw immediate cleanup + `failedIds` isolation, and post-`dispose()` handle guards.
- **`src/profiles/antigravity.js` & Composition Roots (`bin/addon-host.js`, `src/index.js`)**:
  - Wires `ANTIGRAVITY_HOST_PROFILE` and the Electron ports into `createCliApp(...)` (`src/index.js` instantiates the default CLI app lazily on first call). Any other desktop host can supply its own profile and/or ports without modifying `src/core/` or `src/cli/`.
